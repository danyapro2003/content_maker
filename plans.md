# Архитектура проекта Content Clipper (Qt6 / C++)

## Цель
Оконное приложение на Qt6 для автоматического создания виральных вертикальных нарезок (9:16) из видеофайлов (MKV, MP4) с прожжёнными субтитрами «слово-за-словом», в русской и английской версиях.

## Пайплайн системы (реализован)

### Режим 1: «Хайлайты» (виральные моменты)
1. **Анализ метаданных:** `MediaExtractor::runFFprobe` запускает `ffprobe` (JSON: streams, chapters, format) через `QProcess`; `MetadataParser` разбирает JSON в структуру `MediaInfo` (главы, аудио, субтитры; классификация RU/EN по `tags.language` + эвристики по title; bitmap-сабы PGS/DVD отбрасываются как неизвлекаемые в SRT).
2. **Субтитры для LLM:** извлечение выбранных дорожек (`ffmpeg -map 0:s:N`) согласно настройке `subsForLlm` (RU/EN/оба). Если текстовых сабов нет — whisper-транскрибация аудиодорожки (`--vad -mc 0`, VAD-модель silero настраивается).
3. **Мультиагентный отбор хайлайтов (`LlmClient::findHighlights`, OpenAI-совместимый API):**
   - **Аналитик:** метаданные + главы + сабы → синопсис.
   - **Скаут:** текст бьётся на чанки (`scoutChunkChars`), по каждому ищет кандидатов с реальными таймкодами.
   - **Продюсер:** отбирает 3–7 победителей (лимиты в настройках) → строгий JSON; чистка markdown, валидация таймкодов, 1 ретрай.
4. **Снаппинг границ (`SrtUtils::snapSegment`):** границы каждого клипа «прилипают» к границам реплик из SRT (начало → начало первой пересекающейся реплики − `padStartSec`, конец → конец последней реплики + `padEndSec`). Убирает обрывы на полуслове.
5. **Рендер (двуязычный):** для каждого хайлайта и каждого включённого языка (RU/EN): `MediaExtractor::extractAudioWav` (сегмент, 16kHz mono) → `WhisperRunner` word-level сабы (`-ml 1 -sow`, `-l ru/en`, опционально `-dtw <пресет> -nfa`) → `ClipRenderer::renderClip`: один проход ffmpeg (`-ss/-t` + 9:16 blur-bg + `subtitles=...:force_style=...` + `-map 0:a:N`) → mp4.
6. Вывод: `<папка_видео>/<basename>_clips/{ru,en}/clip_NN.mp4` + `clips.json`; временные файлы в `<basename>_clips/temp/`.

### Режим 2: «Пересказ 2.0» (история из склеек, методология video-use)
1–2. То же, что в режиме 1 (метаданные; в subs-режиме — субтитры/whisper-fallback).
3. **Транскрипт фильма** (настройка `storyWhisperTranscript`):
   - whisper-режим: полное аудио → whisper word-level по всему фильму (`-ml 1 -sow` + DTW) → `temp/story_transcript_<lang>.srt`. Кэш: не пересчитывается, если свежее исходника.
   - subs-режим: сабы из файла (как раньше).
   - **[Опционально] диаризация pyannote** (`diarizationEnabled`): `DiarizeRunner` → QProcess(python → `scripts/diarize.py`) → JSON сегментов спикеров (кэш `temp/story_diar.json`). При ошибке — продолжаем без меток.
4. **Упаковка (`TranscriptPacker`)**: слова → фразы (разрыв по паузе ≥ `editPauseSec` или смене спикера) → `movie_packed.md` вида `[312.52-315.36] S0 текст...` — компактная «поверхность чтения» для LLM.
5. **Кадры для визуального контекста** (опционально, `llmSendFrames`): 1 кадр / `frameIntervalSec` сек → `temp/frames/`.
6. **Один запрос в LLM** (`LlmClient::findStories`): packed-транскрипт (+ кадры) → JSON пересказов с **драматургией**: каждая склейка = бит истории (`beat`: HOOK/SETUP/CONFLICT/ESCALATION/CLIMAX/RESOLUTION, `quote`, `reason`), таймкоды в секундах, title/description/caption.
7. **Снаппинг к границам слов** (whisper-режим, паддинг `editPaddingMs`) или реплик (subs-режим, `padStartSec`/`padEndSec`) + слияние близких (`mergeGapSec`, метаданные битов сохраняются).
8. **Рендер:** для каждого пересказа и языка: склейка wav (`extractConcatAudioWav`) → whisper word-level → `renderStoryClip`: concat с **afade 30мс на границах** (`editAudioFadeMs`, убирает щелчки) или xfade/acrossfade-кроссфейды (`storyCrossfadeSec`) + 9:16 + прожиг сабов последними в цепочке.
9. Вывод: `<basename>_clips/{ru,en}/story_NN.mp4` + `stories.json` + `story_NN_caption.txt` + `movie_packed.md`.

### Режим 3: «Пересказ 3.0» — сокращение сюжетной ветки

Цель: несколько отдельных роликов, каждый рассказывает одну ветку от хука и завязки до результата.
События ветки могут быть разбросаны по всему фильму. Отдельные яркие сцены не
заменяют причины решений, развитие и завершение истории.

1. Аудиодорожка RU (или EN, если RU нет) → ASR короткими чанками с абсолютными таймкодами.
2. Карта аудио и независимый ревизор. Спорные окна распознаются повторно по 10 с;
   текст меняется только при согласии ревизора с повторным проходом. Остальные
   расхождения помечаются для LLM. Отсутствие logprob не означает плохую уверенность.
3. Сшивка формирует `s3_clean_words.json`, речевой SRT и packed-транскрипт.
   Очищенные слова общие для анализа, выбора интервалов и прожига RU-субтитров.
   Музыкальные маркеры остаются только в контексте LLM. Второй язык распознаётся
   отдельно по своей звуковой дорожке.
4. **План:** LLM выбирает `minClips`–`maxClips` разных веток. У каждой свой герой,
   цель, исход, подтверждённый хук и 3–8 причинно связанных событий с ID фраз.
   Затем каждая ветка получает отдельный цикл монтажа и проверки. Повторы более
   70% материала принятого ролика отклоняются. При нехватке прошедших проверку
   историй выводится явная ошибка, один ролик не выдаётся за выполненный пакет.
5. **Монтаж:** LLM сохраняет необходимые звенья ветки, убирает повторы и побочные
   линии. Границы задаются ID фраз `start_phrase` / `end_phrase`, а не придуманными
   таймкодами. Цитата подтверждает блок и не сжимает его до длины реплики.
6. **Редактор связности:** отдельный запрос с текстом реального монтажа, исходником, планом и черновым EDL
   проверяет переходы, мотивацию, введение персонажей и развязку, затем возвращает
   исправленный монтаж. Пояснения JSON и вырезанные сцены не считаются знанием зрителя.
   На этих этапах доступен запрос кадров; сетки подписаны временем.
7. Валидатор требует HOOK на 1.5–12 с, затем SETUP, хронологию основной истории,
   решающее событие и RESOLUTION в конце. Хук может быть из будущего, с возвратом
   к завязке, но его кадры не должны повторяться в основной истории. Каждый блок
   основной истории ограничен `s3MaxSegmentSec` (35 с), включая боевые сцены.
   Также проверяются
   реальные цитаты, целые монтажные блоки и соблюдение бюджета. Ошибочная склейка
   отклоняет весь пересказ: нельзя молча выбрасывать завязку или обрезать развязку.
8. Рендер V3 использует прямые склейки и короткие аудиофейды без перекрытия диалогов.
   `stories.json` содержит фактические границы в порядке показа после паддинга и `narrative_plan`.
   Субтитры V3 оформляются в ASS с явным разрешением 1080x1920: короткие фразы до
   четырёх слов, полужирный белый текст с тёмной обводкой. Фразы не пересекают
   монтажные склейки. Размер и число слов настраиваются отдельно для V3.

Начальные параметры: 3–7 историй (`minClips`/`maxClips`), 60–180 с КАЖДОГО ролика,
до 12 фрагментов включая хук, охват исходного фильма
без ограничения (`s3MaxSpanSec=0`). При чтении старых настроек прежние стандартные
значения 20/90/300/6 мигрируют в 60/180/0/12; нестандартные значения сохраняются.
Кэш каждого этапа учитывает источник/дорожку, параметры, скрипты и входные артефакты;
изменённый или повреждённый результат не переиспользуется.

Регрессионные проверки: CMake `CONTENT_CLIPPER_BUILD_TESTS=ON`, `Python3_EXECUTABLE`
указывает на окружение с numpy, затем сборка и `ctest --output-on-failure`.
Тесты не загружают модели и не вызывают внешний LLM API: проверяются цитаты,
длительности, целостность ветки, три этапа LLM на локальном HTTP-имитаторе, очередь
двух фильмов, языки, итоговый EDL, зависимости кэша и Python-очистка транскрипта.
Художественное качество оценивается отдельно на реальных фильмах.

Каждый запуск, в том числе повторный и неудачный, создаёт новую папку
`<basename>_clips/logs/run_<дата>_<время>_<id>/`. В ней сохраняются:

- `run.json`: источник, модель, ограничения количества и длины;
- `application.log`: сообщения конвейера;
- `NNN_<этап>.request.json`: полный JSON запроса (без заголовка Authorization);
- `NNN_<этап>.response.json` и `.response.txt`: сырой ответ API, статус HTTP, время и текст модели;
- `.validation.json`: разрешённые по ID таймкоды и причины отбраковки;
- `narrative_plans.json`, `selection.json`, `final_edl.json`;
- `result.json`: отдельный статус текущего запуска и действительно созданные им файлы.

Повторное добавление исходного фильма всегда заново вызывает LLM, используя кэш
ASR/диаризации. Готовые MP4 не пропускают анализ. Неудачный отбор сохраняет старые
ролики и явно сообщает, что текущий запуск не создал новых результатов.

## Модули
- `AppSettings` — settings.json рядом с exe + вкладка «Настройки» в UI (пути к ffmpeg/ffprobe/whisper-cli/моделям, LLM endpoint/key/model, subsForLlm, языки рендера, лимиты).
- `PipelineManager` — конечный автомат, очередь файлов, оркестрация всех этапов, сигналы прогресса в UI.
- `MediaExtractor`, `MetadataParser`, `LlmClient`, `WhisperRunner`, `ClipRenderer`, `SrtUtils`, `TranscriptPacker`, `DiarizeRunner` — этапы пайплайна.
- `scripts/diarize.py` — pyannote-диаризация (копируется рядом с exe при сборке); venv: `.venv-diar` (Python 3.12).
- `MainWindow` — выбор файла/папки, таблица клипов, лог, настройки.

## Технические детали
- ffmpeg при рендере запускается с рабочей папкой = папка с srt (обход проблем экранирования путей Windows в фильтре `subtitles=`).
- Байты ffprobe парсятся как UTF-8.
- Ошибка на любом этапе → файл пропускается, очередь продолжается.
- Нарезка кадр-точная (перекодирование при прожиге всё равно неизбежно).
- Аудио в клипах: даунмикс 5.1 → стерео (`-ac 2`), AAC 192k (исходники 5.1 в AAC 128k звучали ужасно).
- Стиль субтитров (ASS force_style) вынесен в настройки; дефолт: Segoe UI, белый, без обводки.
- DTW-выравнивание whisper (`whisperDtw`, пресет определяется из имени файла модели: large-v3 → `large.v3` и т.п.): точные word-таймкоды, несовместимо с flash-attn (добавляется `-nfa`). Неизвестная модель → без DTW.
- Отбраковка forced-сабов: в MP4/M4V нет флагов forced в метаданных, поэтому после извлечения SRT проверяется плотность реплик (`minSubsCuesPerHour`, дефолт 100/час; forced ~16/час, полные 500–1500/час). Не прошла → пробуется следующий кандидат этого языка (`MediaInfo::rusSubsCandidates`/`engSubsCandidates`), все не прошли → whisper fallback.
- Кроссфейды (`storyCrossfadeSec`): xfade/acrossfade применяются одинаково и в рендере, и в склейке wav для whisper — иначе сабы разъехались бы со звуком. xfade отключается, если какой-то сегмент короче 2×F.

## Проверено
- Парсер на реальном ffprobe JSON (Avengers): корректные индексы дорожек, отброс PGS-сабов.
- whisper-cli word-level (`-ml 1 -sow`): по одному слову на cue; DTW (`-dtw large.v3 -nfa`) работает.
- Рендер: 1080x1920, blur-bg, прожжённое слово — визуально проверено.
- `SrtUtils`: юнит-тест parse/snap/merge на синтетическом SRT — все ожидания совпали.
- `TranscriptPacker`: юнит-тесты — разрыв фраз по паузам и по смене спикера (S0/S1 по порядку появления).
- afade 30мс на склейках: проверено ffmpeg (3×5с concat → 15.0с, без щелчков).
- xfade/acrossfade-цепочки (3 сегмента × 5 сек, фейд 0.25): длительность 14.51 c (видео) и 14.50 c (wav) — совпадает с расчётом 15 − 2×0.25.
- extractFrames: 199 кадров 640px на фильм 2ч29м (interval 45с), ~4–5 МБ суммарно в base64.
