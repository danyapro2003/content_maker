# Реализация и проверка исправлений V3

Состояние на 14 ноября 2026 года. Подробное техническое задание: `V3_FIX_PLAN.md`.

## Что работает в коде

- Строгий разбор ответов с отдельными ошибками формата, ссылок, границ и смысла.
- Кэш проверенных окон карты событий, импорт старого анализа, режим продолжения.
- Журнал фактических POST, общий бюджет и защита от повтора запроса с неизвестным исходом.
- Основные и запасные сюжетные ветки, контекст отдельных веток вместо полного фильма в каждом запросе редактора.
- Один окончательный монтаж: время, длительность, покрытие событий и хэш одинаковы для аудитов и рендера.
- Проверка зрителем без замысла редактора и отдельная проверка верности исходнику.
- Ограниченное число исправлений, запрет повторного аудита неизменившегося монтажа.
- Частичный результат сохраняется; ошибка одной истории/языка не уничтожает другие ролики.
- Отдельная папка каждого запуска; готовность MP4 подтверждается ffprobe перед публикацией имени файла.
- Итоги очереди показывают фактические новые файлы, а не просто факт окончания обработки.

## Практические проверки

Локальная сборка: `build/v3_recovery`. Три группы CTest: `stories3`, `transcript_v3`, `llmtransport`.
Проверяются в том числе несуществующие ID, перекрытия ASR, бюджет, кэш, две истории,
ошибка EN при успешном RU, неверная длительность выходного файла и сохранение старых результатов.

Проверка формата gpt-6-astra через lenec.tech: два синтетических запроса, оба правильные,
1211 токенов по ответам провайдера. Содержимое фильмов для этой проверки не использовалось.

Первый реальный анализ «Человека-паука»:

- Логи: `D:/филм/Spider.Man.Far.from.Home.1080p.HD_clips/logs/run_v3_validation_20261114_01`.
- 481 событие импортировано и перепроверено; десять окон индексации не отправлялись повторно.
- 6 POST из лимита 12, 133218 токенов по данным провайдера, неизвестных исходов 0.
- Принята одна история, 122.96 секунды; MP4 создан и проверен.
- Видео: `D:/филм/Spider.Man.Far.from.Home.1080p.HD_clips/runs/validation_20261114_01/ru/story_01.mp4`.
- Проверка выбранных реплик выявила слабость несмотря на pass обоих аудиторов:
  24 секунды общей предыстории и недостаточно подготовленный переход к позднему финалу.
  Этот результат подтверждает технический путь до MP4, но НЕ художественную готовность.
- После этого промпты уточнены: один драматический вопрос, непосредственный конфликт в начале,
  явные причинные переходы, запрет достраивать связь между событиями по знанию фильма.

Следующий прогон: три основных ветки и две запасные, лимит 36 POST,
логи `run_v3_validation_20261114_02`. Итоги ещё требуют оценки.
Для проверки переносимости готовится локальный ASR «Дома у озера»; «Дикий, дикий Запад»
выбран следующим независимым исходником. Пользователь явно разрешил отправку текста этих
трёх фильмов через lenec.tech в пределах указанных бюджетов.

## Диагностические команды

Команды реализованы в `tests/live_v3_run.cpp`, доступны через `test_stories3.exe`:

```text
--check-live-model settings.json logs-directory
--prepare-v3 settings.json source
--preview-v3 settings.json source packed.md import-log-dir-or-dash logs-directory count [budget]
--live-v3 settings.json source packed.md import-log-dir-or-dash logs-directory count [budget]
--render-v3 settings.json source packed.md clean-words.json evaluation_result.json output-directory
```

`--prepare-v3` выполняет локальный ASR, ревизию и диаризацию, останавливаясь перед первым POST.
`--preview-v3` сохраняет фактический запрос без отправки. `--live-v3` анализирует, но сам
не рендерит; `analysis_complete` не означает готовые видео. Диагностический рендер выбирает
язык кэшированной расшифровки и проверяет отпечаток исходника и хэш принятого монтажа.
В обычном приложении сохраняется обработка RU/EN. Диагностические ролики не меняют
указатель последнего пользовательского результата.

## Что пока нельзя считать подтверждённым

- Полный просмотр нескольких роликов со звуком и оценка естественности стыков человеком.
- Переносимость на три разных фильма: проверки ещё идут.
- Визуальная причинность и немые действия: визуальный этап не реализован в этой работе.
  Текстовый аудитор должен возвращать needs_visual, если без изображения понимание невозможно.
- Pass LLM сам по себе не гарантирует приятного монтажа; первый реальный пример это показал.

Не ослаблять проверки ради количества файлов. Не менять пользователю исходники, ключи API
или настройки ради диагностического прогона. Логи и медиакэш не добавлять в Git.
