# V3: сокращение связной истории

Исходная рабочая версия: коммит `6ae523b` на `master`.
Разработка: `codex/v3-narrative-pipeline`.

## Цель

Для разных фильмов выбирать несколько историй с интересным началом и подготовленным
завершением. Сохранять причины, изменения знаний и реакции. Завершением может быть
результат, раскрытие или шутка; весь конфликт фильма разрешать не требуется.
Имена и события выводятся из конкретного исходника. Примеры из «Человека-паука»
служат материалом оценки, не встроенным шаблоном.

## Этап 1 — реализован: смысловая сборка по речи

1. Существующий ASR/ревизор/диаризация формируют фразы со стабильными ID.
2. Фразы разбиваются на окна примерно по 14 000 символов с перекрытием двух фраз.
   Каждый запрос карты независим. События содержат `observed`, `viewer_requires`,
   `viewer_learns`, `character_knowledge`, `uncertainties`, `evidence_phrase`, `quote`.
   Код проверяет уникальность ID окна, реальность фразы и точность цитаты.
   Доказательство из сомнительной фразы не принимается. Координаты берутся из исходника.
3. Планировщик выбирает заданное количество замыслов. Для каждого задаёт `ending_event`
   и `required_events`, учитывая необходимые знания зрителя. Содержание связей
   дополнительно оценивает зритель: метаданные сами по себе не доказывают связность.
4. Монтажёр получает карту, план и исходник. Каждый выбранный блок связывается с
   `event_ids`; код проверяет присутствие доказательств обязательных событий.
   Последний блок содержит доказательство выбранного завершения.
5. Естественное начало (`natural`) может одновременно быть хуком и завязкой.
   `cold_open` допускает один возврат после начального блока <=12 с. Остальная
   последовательность сохраняет порядок исходника. Повтор материала отклоняется.
   Один интервал может содержать несколько событий. Минимума в четыре блока нет.
   Ориентир длины блока 35 с больше не является жёстким пределом; общий бюджет строгий.
6. Зритель получает новый диалог: только выбранные полные реплики, нейтральные номера
   блоков и время ролика. Исходник, название, план, event/connection, предыдущие ответы
   и source ID отсутствуют. Доступа к инструменту кадров у этого запроса пока нет.
7. После положительной оценки зрителя отдельный запрос сверяет смысл с исходником.
   Проверяющие возвращают пересказ понимания, `pass` и проблемы с номерами блоков.
8. Замечания любого проверяющего поступают редактору с исходником. Не более двух
   исправлений на ветку, после каждого — обе проверки заново. Для ошибки формата
   разрешён один повтор запроса. Противоречивый/неполный audit не считается успехом.
9. При недостаточном количестве принятых историй рендер не запускается; причины
   доступны в logs. Автоматическая генерация запасных замыслов ещё не реализована.

Рабочие промпты: `storynarrative.cpp`; управление этапами: `llmclient.cpp`.
ASR-кэш сохранён. Карта событий пока строится при каждом запуске LLM и записывается
в `event_map.json` текущего запуска; повторное использование карты ещё не реализовано.
Пользовательские значения длительности сохранены, короткий профиль пока не добавлен.

## Этап 2 — предстоит: визуальные события и стыки

- Карта смен планов и обзорные последовательности кадров; подробная проверка
  значимых молчаливых участков. Смена камеры не равна событию.
- Доказательства `visual`/`mixed` с проверенными интервалами и просмотренными кадрами.
  У молчаливой реакции не требовать цитату.
- Зрителю — только кадры оставленного материала в порядке ролика. Исключённые кадры
  и описания монтажёра не должны проникать в этот запрос.
- Проверка стыков по хвосту предыдущего и началу следующего фрагмента. Уточнение
  границ по завершению реплики/действия, паузам и планам, проверка после паддинга.
- Неподтверждённое визуальное звено не считать автоматически понятным. Сейчас зритель
  может вернуть `visual_gap`; до внедрения изображений такие истории могут отклоняться.
- Версионированный кэш карт по исходнику, транскрипту, параметрам извлечения,
  модели и версии промптов. Адресное получение недостающего контекста.
- Резервные замыслы в пределах явного бюджета запросов.

## Этап 3 — предстоит: оценка на разных фильмах

- Разные жанры, в том числе малословное кино. Часть фильмов не использовать
  для настройки промптов, чтобы отдельно проверить переносимость.
- Оценивать понимание без знания фильма, подготовку финала, сохранение смысла,
  естественность границ и отсутствие лишних повторов.
- Сравнение с baseline на одинаковых исходниках и настройках.
- Короткий профиль длительности без перезаписи явно заданных значений.
- Поясняющие надписи: только подтверждённые материалом, реально отрисованные
  и включённые в проверку зрителем.

## Проверки и логи

Локальный HTTP-имитатор проверяет разные исходники и несколько историй, изоляцию
контекста зрителя, обязательные доказательства, повтор после исправления, отклонение
невалидного audit, предел исправлений, сохранение прежнего результата при неудаче,
RU/EN рендер и кэш ASR. Это проверки программы, не художественного качества LLM.

Логи содержат запросы/ответы `index`, `plan`, `edit`, `viewer`, `fidelity`, `repair`,
`event_map.json`, планы, `.audit.json`, `.validation.json`, финальный EDL и статус.
Ключ API в них не записывается.

Временные HTTP 408/429/500/502/503/504 и отдельные сетевые сбои повторяются
внутри того же запроса: до четырёх попыток, паузы 60/120/180 с. Это не расходует
ходы монтажёра и не добавляет сообщений в диалог. `Retry-After` (секунды или дата)
может увеличить паузу; ожидание свыше 10 минут останавливает автоматический повтор.
Одна попытка ограничена 5 минутами. Ошибки авторизации, остальные постоянные HTTP
ошибки и пустой/неверный успешный ответ не повторяются на сетевом уровне.
Каждая попытка сохраняет запрос и ответ (`_attempt_02`, ...), HTTP-статус,
время ожидания и решение о повторе. Смена запуска отменяет старый запрос и таймер.

Сборка копирует Python-скрипты через `copy_if_different`: неизменённые файлы
сохраняют время модификации, поэтому пересборка C++ не сбрасывает ASR-кэш.
Формат ключей кэша прежний; изменение скрипта, параметров или артефакта по-прежнему
требует пересчёта зависимых этапов. Сетевые повторы и сохранение кэша проверяются
отдельным тестом `llmtransport` на локальном HTTP-сервере.

Полный прогон фильма через внешний LLM после изменений ещё не выполнен.
